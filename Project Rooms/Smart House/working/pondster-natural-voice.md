## Prepared implementation

- The persistent Pondster panel adds Natural conversation with Browser voice and typed questions retained. Starting is explicit. No microphone is acquired on page load, opening the panel, or selecting a mode. The interface discloses AI voice and audio transmission to OpenAI before starting.
- WebRTC carries audio between the browser and OpenAI. The website's same-origin control WebSocket creates a fixed server-configured session and attaches a trusted server sideband before returning the SDP answer. The API key stays on the server. Browser data-channel permission allows only `session.close`; it cannot change instructions or send trusted answers.
- Only authored public website facts enter the session: current gallery choices, planned features, static Jean Wright credit, verified realtor/builder contacts, the design tour, and honestly simulated viewing. The location, internal source records, private owner information, and actual devices remain unavailable. A bounded public resolver answers delegated questions and validates public navigation actions.
- Close, Stop, Escape, hidden tab, unmount, connection failure, and interrupted setup release browser capture/playback. A bounded close handshake asks the provider to finish. Transcript captions and recent messages stay in temporary browser/Worker memory; the website database stores no audio, transcripts, SDP, or raw IP addresses. This describes the website's storage, not OpenAI's separate data handling.
- D1 metadata supplies request deduplication, 20 attempts globally per rolling 24 hours, four per visitor browser, a 60-second browser cooldown, and two concurrent sessions globally/one per browser. Typed requests are limited to 20 per session and one per two seconds. These anonymous browser limits do not verify a person and cannot stop cookie replacement by themselves.
- Browser and server request termination at three minutes. Worker timers are not durable through a crash/eviction, so this is **not an absolute billing cap**. Unconfirmed provider closure leaves its reservation occupied until an administrator verifies and reconciles it; expiry alone does not release it. Do not blindly mark an uncertain session closed. The server also bounds setup and the final close drain. The provider has no documented configurable hard session lifetime in the reviewed contract.
- `PONDSTER_VOICE_ENABLED=false` disables new availability. Runtime key names are documented without values in `.env.example`. The generated `voice_sessions` migration is additive and preserves votes/comments.
