# Gnatt Chart Mode Rules

Use these rules when designing, repairing, or rolling out the `Gnatt Chart` worksheet in Buy Your Home project-management spreadsheets.

The workbook sheet is currently named `Gnatt Chart`. Keep that spelling unless Wes explicitly approves a sheet rename.

## Profit Reconnect Rules

- When reconnecting Profit to `Gnatt Chart` expense totals, do not assume the approved template's source cell applies to every project. Map the `Gnatt Chart` total by label and old/source formula for each workbook. Known Pond example: Tensity used `Gnatt Chart!J5` for `Profit!B66`, but Pond's old Profit used `Gnatt Chart!I6`, where `F6` is labeled `Grand Total`; copying `J5` left the expense at zero.
- When a migrated Profit row feeds an adjacent percentage or payout row, remap and validate the paired downstream formula at the same time. Known Pond example: fixing new `Profit!B66` to the correct `Gnatt Chart` grand total was not enough; new `Profit!B68` still used the copied template formula `=IF(M13,0,+B67*SUM(B66:C66))`, while old Pond calculated Murphy's Cut from the Gantt total because old `Q12` was blank. The corrected Pond formula was `=+B67*SUM(B66:C66)`, matching the old Murphy's Cut value.

## Name And Link Validation

- For every Gnatt Chart worksheet update, scan sheet-scoped defined names for unintended external references before upload. Copied worksheets can carry source-workbook names even when the copied cells look clean.
- Verify Excel's workbook-link list and break unintended project-workbook links before uploading the cleaned workbook.

## Lesson Capture

- November 4, 2026 Pond Gnatt synchronization repair: do not sort a formula-driven editable table immediately inside change/calculation events. Coalesce requests into a deferred callback, wait for query activity to finish, temporarily disable events and use Manual calculation, then calculate/sort until Order stabilizes. Use the same Order-then-Index tie break in the editable table and Power Query. Refresh the dependent query and verify every displayed left/right Index, not just the first repaired row. Bound stabilization/retry attempts and report failure visibly instead of silently accepting a mismatch.
- Keep whole editable records together. Compare the complete formula/input multiset before and after sorting, including unused and duplicate legacy records; do not discard them merely to simplify synchronization. Pond had 202 displayed records and 270 editable records. Existing inactive duplicate indexes 237 and 913 remain a separate data-quality issue, not authorization to delete or merge records.
- Native Excel sorting keeps grid borders at worksheet coordinates while other cell formatting follows records. Validate borders by coordinate and other formatting/formulas/inputs by record. A raw style-ID comparison is not proof of a changed appearance.
- A valid ListObject can have no AutoFilter object when filter controls are absent. Check for Nothing before reading FilterMode. Use a handled text-result entry point for automated VBA tests so expected errors do not escape Application.Run as desktop Debug dialogs. Test failure cleanup as well as success, preserving the caller's calculation, events and screen state.
- Use native QueryTable AfterRefresh watchers and cancel pending OnTime callbacks on close. Test rank changes, equal-rank ties, unapprove/reapprove, query refresh, Refresh All, idle behavior and Manual-mode restoration on a disposable copy, then repeat on the exact delivered Teams download. Do not save test edits. Keep the separately deferred Full Recalc redesign distinct; adding a synchronization callback does not resolve its asynchronous-refresh or checkbox-mode defects.
- Before replacing Teams content, compare against the actual repair source ETag, not an earlier inspection version. If an upload safety check flags a possible newer save, fetch current bytes again and prove identity to the validated source before retrying the same connector action. A changed source requires remapping and revalidation, not an overwrite.
- When moving an editable override column to the left edge of its native table, move the complete table column, including its header, formats and metadata; move its width with it. Keep merged banners and adjacent tables in place. Reapply the existing table sort before saving because native cut/insert can leave a saved sort-range reference starting at the old first column. Resolve Index and price columns by header name in validation as well as VBA; do not leave a test selecting the former price-column address. Verify all prices by Index and repeat automatic-edit and sort/refresh tests on the delivered copy.
- November 4, 2026 Pond adjacent-price design: independent override tables may follow the main table's displayed order, but Index remains the key. Sort the entire override record, never just its Index or amount column. Keep inactive indexes below active rows, add new indexes with blank overrides, and refuse duplicate or invalid indexes. Hide calculated prices only when the nearby editable column is clearly identified; macros must be enabled for automatic visual alignment, while price lookup itself remains Index-based without macros.
- Filters on one table hide entire worksheet rows and can cause a neighboring table's native sort to skip records. Capture and restore supported main-table filter criteria and hidden-row state while aligning all records. Preserve the owner's active filter. Reject an independently filtered override table or unsupported special filter with a clear warning instead of silently doing a partial sort. Include filtered rows in the sort/refresh tests, not just an unfiltered example.
- Refresh and sort events can fire before Excel finishes changing a query table. Defer event-triggered alignment until Excel is ready, check the refresh state, retain a selection/activation safeguard, and cancel scheduled callbacks on close. Batch alignment under temporary Manual calculation, write helper values as one array, and restore caller settings on success/error. A narrow sorting change should add only an alignment callback to an existing Full Recalc routine; do not expand into the separately deferred checkbox/recalculation redesign or claim its issues are resolved.
- VBA's editor can change identifier capitalization in unrelated modules when new generic variable names are added. Compare all pre-existing module text and use specific new identifier names rather than accepting unrelated VBA churn. Native Excel may serialize a default row height as the equivalent explicit height; compare effective height, not just the presence of the XML attribute.
- November 3, 2026 Pond Others pricing repair: never keep manual price overrides only beside a refreshable query result. Reassignment in Contract changes the filtered row list, while unbound literal columns can stay in their former worksheet cells. Pond's historical Others!H21 was item 59/Drywall/$4,640; it became item 45/Tile Shower with the same $4,640. Store overrides in an independent native table keyed by immutable item Index, and look them up from the query table. Sort, removal/reinsertion, and refresh must retain prices by Index, not position.
- Preserve explicit zero overrides separately from blanks. A blank/missing override uses the current Contract unit price; zero means zero. Guard duplicate Index entries visibly instead of silently accepting the first match. Do not blanket-copy Contract prices over project-specific overrides. Recover historical values by Index only after comparing an earlier mapped version, a pre-edit baseline, and the latest owner save; retain later owner changes and document the mapping basis per item.
- Inspect each contractor's pricing logic independently. Tim's Unit Price 2 is a Days-based formula (or Contract price when Days is zero), with Days retrieved by Index. Others had literal overrides. Do not apply an Others repair to Tim merely because column headers match. Validate native query refresh, automatic override edits, blank fallback and sort/reassignment behavior on a disposable copy and again on the exact delivered Teams download; discard all test changes.
- November 3, 2026 Pond header repair: `Contract_Edits` column 6 at `Gnatt Chart!Q24` was named `0` instead of `Paid`. A structured reference such as `Contract_Edits[0]` refers to that literal header, not a zero-value fallback. Rename the native table column and verify all dependent formulas across every worksheet, not just Gnatt Chart. In Pond, 222 formulas across Depends, Glasgow, Tim, Others and Gnatt Chart followed the rename; 279 source rows were retained.
- Check VBA, defined names and Power Query separately: Excel's native table rename is not proof that references inside code or text strings were updated. Do not globally replace the number zero. Preserve query logic and do not trigger an unrelated data refresh for a header-only repair. Compare recalculated source and result values in the same engine, then recheck the saved/downloaded file; old cached results alone are not a reliable baseline.
